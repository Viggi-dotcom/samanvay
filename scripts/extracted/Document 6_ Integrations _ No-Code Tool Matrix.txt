Stack Justifications
Why WeWeb over Bubble
Bubble utilizes a proprietary backend that struggles with complex SQL joins across millions of
records and does not support native PostgreSQL Row-Level Security. WeWeb compiles to
standard Vue.js/Vite Single Page Applications, connects directly to external databases via
standard REST/GraphQL APIs, and natively integrates with Supabase authentication and RLS.
Why Supabase over Firebase/Airtable
Airtable hard-caps base records (typically 50k to 125k), failing the volume requirements of
national governance datasets. Firebase NoSQL Firestore) cannot natively perform multi-table
relational joins, geographic entity lookups, or enforce complex SQL-level RLS policies.
Supabase provides enterprise-grade PostgreSQL handling relational depth, JSONB payloads,
and spatial queries via PostGIS.
Why n8n over Zapier/Make
National government datasets contain millions of rows requiring heavy batch ingestion. Make
and Zapier charge per-task fees that become cost-prohibitive at scale and impose payload size
limits (typically 5MB to 10MB. Self-hosted n8n operates with zero per-run execution costs,
supports deployment within sovereign cloud boundaries, and handles large data streaming
pipelines with full control over timeout and retry policies.

Integration 3 GIS Vector Tile Server NIC / Mapbox Services)
● Purpose: Renders interactive, pan-and-zoom India administrative boundaries down to
district and block levels.
● Auth Method: URL Query Token or Access Token (access_token=<MAP_TOKEN>).
● Endpoint Pattern: GET
gis-tiles.internal.domain/v1/tiles/lgd/{z}/{x}/{y}.pbf?layer=district
&year=2026
● Response: Protocol Buffer Vector Tile (.pbf) dynamically parsed by Mapbox GL /
MapLibre JS running inside the WeWeb custom application frame. Boundaries bind
directly to dim_lgd_geography.lgd_code feature properties to enable real-time
thematic color fills based on Postgres query outputs.
